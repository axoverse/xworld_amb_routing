## Project Overview

**xbase_plugin** is a Godot 4 `@tool` editor plugin (`plugin.cfg` → `xbase_plugin.gd`) for the Axoverse Studio pipeline. It processes building/facility models imported from Revit (via Asset Management) and prepares them for export to the Axoverse XScape platform and ROS2 robot navigation.

The plugin provides an editor dock with buttons that trigger its main tools, plus headless runner scripts for CI/batch use.

### Key Concepts

- **TSCN scenes** are Revit-exported building models with nodes organised under groups: `Walls/`, `Floors/`, `Rooms/`, `Doors/`, `Beds/`
- **Level scenes** live under a `levels/` directory; a site/master scene references them
- **Asset Management metadata** is stored as Godot node metadata (`metadata/element_id`, `metadata/family_name`, etc.)
- **AxNode3D** is the core custom node type that carries ThingLink, Layer, Edge, and export properties
- **GLTF extras** are the export format — numbered component entries written into `.glb` node extras
- **Shared resources** (`.tres` meshes and materials in `shared/`) are generated by the C# Revit extension in `src/avss_sync` (see `TscnMaterialHelper.cs`, `PerLevelTscnExportSink.cs`). The xbase_plugin consumes these resources (e.g. `AREA_MATERIAL_PATH`) but does not create them.

## Core Scripts

### axNode3D.gd (`class_name AxNode3D`)

The central custom node type (`@tool extends Node3D`). Every node that participates in the Axoverse export pipeline gets this script attached.

**Feature toggles** control which property groups are visible in the inspector:
- `useThingLink` → ThingLink properties (ParentOverride, PhysicalType, ThingNameOverride, ThingGuid, etc.)
- `useLayers` → Layer properties (Layers string, LayerFlags bitmask)
- `useEdges` → Edge properties (Edges string, EdgeFlags bitmask)
- `usePivotOverride` → Pivot rotation + camera distance
- `useLabel3D` → Runtime 3D label
- `isRoutingWaypoint` → Marks node as a navigation waypoint

**PhysicalType** is an `@export_enum` with ~66 values (Site, Building, Ward, Level, Room, Bed, etc.) kept in sync with `share/data/physical_types.json`. The runtime helper `physical_type_to_index()` loads from JSON.

**GUID generation**: `_enter_tree()` auto-generates a 32-char hex GUID (`ThingGuid`) if empty. This persists across saves.

**GLTF extras**: `_update_gltf_extras()` mirrors key properties into a `metadata/extras` dictionary used by the export extension.

### sync_am_thinglink.gd (`class_name SyncAmThingLink`)

Syncs Asset Management metadata from imported Revit scenes to AxNode3D properties. Runs as a two-phase scan:

**Phase 1 — Filesystem scan**: Recursively scans `res://` for `.tscn` files, skipping `addons/`, `.godot/`, `build/`, `shared/`. Identifies candidates via line-matching for `metadata/element_id`, level-path detection (`/levels/`), or level instance references.

**Phase 2 — Godot API processing**: Loads each candidate scene, processes nodes:
- **ThingLink enablers** (`THINGLINK_ENABLERS` dict): Maps `family_name` → `PhysicalType`. Sets `useThingLink = true` and assigns the type.
- **Layer enablers** (`LAYER_ENABLERS` dict): Maps `family_name` → `{layer, flags}`. Sets `useLayers = true` with layer name and bitmask.
- If a node needs either, the `axNode3D.gd` script is attached. If neither is needed and `override_existing` is true, the script is removed.
- **Level roots** get `PhysicalType = "Level"` + `useThingLink = true`
- **Site roots** get `PhysicalType = "Site"` + the project name as `ThingNameOverride`

**Ward block creation** (level scenes only): Parses room numbers like `RM-L6-A1-AGWS-01107` to extract block/level/room-type. Groups ward-type rooms (GWS, HDU) into `Ward<level>_<block>` MeshInstance3D nodes under a `Wards/` group, each with a bounding-box transform computed from member room AABBs.

**Bed-to-room assignment** (level scenes only): Spatially assigns beds to rooms via point-in-AABB test — each bed's origin is tested against all room bounding boxes, picking the smallest containing room.

**Headless usage**:
```bash
godot --headless --editor --script res://addons/xbase_plugin/SyncAmThingLinkHeadless.gd
```

### xbase_plugin.gd (EditorPlugin entry point)

Registers project settings under `xbase_plugin/settings/*` (version, company_name, project_name, program_data_dir, verbose_logging, brotli_sidecars). Creates the editor dock and wires buttons:

| Dock Button | Action |
|---|---|
| Export Scene to GLB | Scans for `AxoExport = true` scenes, exports GLB + ThingLink CSV + XWAB manifest |
| Sync AM ThingLink | Runs `SyncAmThingLink.execute()` |
| Add ThingLink Data | Attaches `axNode3D.gd` to the selected node |

> NavMesh baking and ROS2 occupancy-grid generation have moved to the first-party
> **avss_asmgt** plugin (`ext/avss_asmgt_plugin`), which owns its own editor dock and
> the `avss_navmesh_headless.gd` headless runner.

**GLTF export pipeline**: Registers `axo_gltfex.gd` as a `GLTFDocumentExtension`. On export, `_export_node()` writes numbered component entries (ThingLink, BoundsHelper, Layer, Edge, PivotOverride, TransformLock, RoutingWaypoint, CollisionShape) into GLTF node extras. The ThingLink component includes `ThingGuid` and, when `ParentOverride` is set, a `_nodeRefs` sub-object containing the target's GLTF node index (resolved via `GLTFState.get_node_index()`).

**Brotli sidecars** (`xbase_plugin/settings/brotli_sidecars`, default **on**): after each `.glb` and `.pck` is finalized (right where its `.sha256` sidecar is written — `XFabExporter_geometry` for the GLB, `XFabExporter_pck` for the native export-pack `.pck`), the exporter emits a Brotli-compressed `<artifact>.br` sidecar next to it (`Simple.glb` → `Simple.glb.br`). This mirrors the client-side Brotli step Unity does at load time — pre-compressing at export means the runtime/CDN can serve the `.br` directly. Sidecars are logged with original + compressed sizes; they are **not** added to `catalog_default.json` (the catalog carries only the `sha256`/`size`/`glb_sha256`/`glb_size` integrity keys).

- **OS dependency**: requires the `brotli` CLI on `PATH`. Dev boxes and CI build containers must install the `brotli` package (Fedora/RHEL: `dnf install brotli`; Debian/Ubuntu: `apt-get install brotli`; Windows: the `brotli.exe` from the [google/brotli releases](https://github.com/google/brotli) on `PATH`). The exporter invokes `brotli` by bare name — `OS.execute` resolves it via `PATH` (execvp on Unix, `CreateProcess` on Windows).
- **Graceful degrade**: availability is probed once per export run via `brotli --version`. If the CLI is missing or the probe fails, the exporter `push_warning`s **once** and skips all sidecars — the export itself never fails because Brotli is unavailable. Turning the setting off skips the probe and emits no sidecars (and no warning).
- **Compression quality**: `-q 6` (see `BROTLI_QUALITY` in `xbase_plugin.gd`). `q=11` is the web-static-asset default but was measured at ~135 s per 100 MB pack on a dev box (prohibitive for a default-on export step) while `q=6` matches its ratio on large binary asset payloads at ~1 s per 100 MB (the nginx Brotli module's own default balance). Invocation: `brotli -f -k -q 6 -o <artifact>.br <artifact>`.

### Shared Data Files (`share/data/`)

JSON files are the source of truth for enum values:
- `physical_types.json` — 66 physical type names
- `layers.json` — 27 layer names
- `edges.json` — 16 edge type names

These are loaded at runtime by `AxNode3D._load_physical_types()` and used by the Python `ThingLinkInjector`. The `@export_enum` annotations in GDScript must be manually kept in sync (see `share/docs-devel/backlog/codegen_from_json.md` for planned auto-generation).

## Testing

Tests use a combination of GDScript (Godot headless) and Python (pytest + pygltflib).

**Quick start**:
```bash
# All tests (Python + Godot subprocess):
cd godot_proj/addons/xbase_plugin
pytest

# Python-only:
pytest -m "not godot"

# Godot-only:
godot --headless --editor --script res://addons/xbase_plugin/tests/test_runner.gd -- --all
```

For full details on test fixtures, GLTF validation, custom scene testing, and adding new tests, see [share/docs-devel/testing.md](share/docs-devel/testing.md).

## Conventions for Agents

- All tool scripts are `@tool extends RefCounted` (stateless, instantiate-and-execute pattern)
- Headless runners are `extends SceneTree` with `_init()` entry point
- Statistics are tracked as instance vars and printed in `_print_summary()`
- Verbose logging is controlled by `xbase_plugin/settings/verbose_logging` project setting
- Scene modifications follow: instantiate → mutate → `PackedScene.pack()` → `ResourceSaver.save()`
- When adding new family mappings, update both `THINGLINK_ENABLERS` and `LAYER_ENABLERS` in `sync_am_thinglink.gd`
- When adding new physical types, update `share/data/physical_types.json` AND the `@export_enum` in `axNode3D.gd`
- Node references (e.g. `ParentOverride`) cannot be serialized directly into GLTF; use the `_nodeRefs` convention — a sub-object within the component containing `{ "FieldName": gltf_node_index }`. The Unity consumer resolves these indices back to GameObjects in `EndScene`.
